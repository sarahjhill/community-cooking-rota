Register, log in and log out
— with a role chosen at signup

Every step, in order, for macOS. Written for someone who has not built Django authentication before. Nothing is assumed except that your site already runs.

00What you are building

By the end of this you will have four working things:

  • A signup page where someone picks Organiser or Cook as they register
  • A login page
  • A logout button
  • Nav links that change depending on whether someone is signed in
Why you are not installing anything. Django ships with a complete authentication system — users, password hashing, login, logout, sessions. You are not building auth. You are wiring up what is already there and adding one extra field. Your Profile model with its ROLE_CHOICES already exists, so the role has somewhere to live.

01Turn on Django's built-in auth pages

Django already contains the login and logout views. You just have to give them a URL.

config/urls.py 
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("accounts/", include("django.contrib.auth.urls")),
    path("", include("rota.urls")),
]

That single accounts/ line gives you all of these at once:

URLWhat it doesName to use in templates
/accounts/login/The login pagelogin
/accounts/logout/Logs the user outlogout
/accounts/password_change/Change passwordpassword_change
Order matters in that list. path("", include("rota.urls")) must stay last. Django checks patterns top to bottom and stops at the first match. An empty pattern near the top would swallow everything below it.

02Tell Django where to send people

Add these three lines to the bottom of your settings file, just above DEFAULT_AUTO_FIELD.

config/settings.py 
# Where to send people after logging in, after logging out, and where to
# send them if they hit a page that needs a login.
LOGIN_REDIRECT_URL = "rota:home"
LOGOUT_REDIRECT_URL = "rota:home"
LOGIN_URL = "login"
Why rota:home and not /. That is the URL's name, from app_name = "rota" in your rota/urls.py. Using names means if you ever change the actual address, every link and redirect follows automatically. Hardcoded slashes rot.

03Build the signup form

This file does not exist yet. In VS Code, right-click the rota folder → New File → name it forms.py.

rota/forms.py 
from django import forms
from django.contrib.auth.forms import UserCreationForm
from django.contrib.auth.models import User

from .models import Profile


class SignUpForm(UserCreationForm):
    """Django's normal signup form, plus the Organiser/Cook choice."""

    email = forms.EmailField(
        required=True,
        help_text="We use this to send you rota updates.",
    )
    role = forms.ChoiceField(
        choices=Profile.ROLE_CHOICES,
        widget=forms.RadioSelect,
        label="I am signing up as",
    )

    class Meta:
        model = User
        fields = ["username", "email", "password1", "password2"]

    # Show the fields in a sensible order rather than Django's default.
    field_order = ["username", "email", "role", "password1", "password2"]
What UserCreationForm already handles for you: checking the two passwords match, rejecting passwords that are too short or too common, refusing a username that is taken, and hashing the password so it is never stored readable. You are inheriting all of that and adding one field.
Why role is not in Meta.fields. That list is for fields that belong to the User model. role belongs to Profile, so you declare it on the form by hand and save it yourself in the next step.

04Write the signup view

Replace the whole contents of rota/views.py with this.

rota/views.py 
from django.contrib import messages
from django.contrib.auth import login
from django.shortcuts import redirect, render

from .forms import SignUpForm
from .models import Profile, Rota


def home(request):
    """Landing page: every rota, newest start date first."""
    return render(request, "rota/home.html", {"rotas": Rota.objects.all()})


def signup(request):
    """Create a User, attach a Profile with their chosen role, sign them in."""
    if request.method == "POST":
        form = SignUpForm(request.POST)
        if form.is_valid():
            user = form.save()
            Profile.objects.create(user=user, role=form.cleaned_data["role"])
            login(request, user)
            messages.success(
                request,
                f"Welcome, {user.username}. Your account is ready.",
            )
            return redirect("rota:home")
    else:
        form = SignUpForm()

    return render(request, "registration/signup.html", {"form": form})
Read the shape of that view. It is the standard Django form pattern and you will write it again for every create and edit page in this project:
— POST means the form was submitted, so validate it.
— Valid means save, then redirect.
— Anything else (a first visit, or a form with errors) means render the page.
Why redirect instead of render after saving. If you render, the browser's address bar still says "this was a POST", so refreshing submits the form a second time and creates a duplicate. Redirecting makes refresh harmless. This is called Post/Redirect/Get, and it is a rule, not a preference.

06Create the two templates

Django looks for login and signup templates in a folder called registration. The name is not optional.

In VS Code: right-click templates → New Folder → registration. Then create the two files below inside it.

templates/registration/login.html 
{% extends "base.html" %}

{% block title %}Log in &mdash; Community Cooking Rota{% endblock %}

{% block content %}
  <h1>Log in</h1>

  <div class="card form-card">
    {% if form.errors %}
      <p class="form-error">That username and password don't match. Please try again.</p>
    {% endif %}

    <form method="post">
      {% csrf_token %}
      {{ form.as_p }}
      <button class="btn" type="submit">Log in</button>
    </form>

    <p class="muted">
      No account yet? <a href="{% url 'rota:signup' %}">Create one</a>.
    </p>
  </div>
{% endblock %}
templates/registration/signup.html 
{% extends "base.html" %}

{% block title %}Sign up &mdash; Community Cooking Rota{% endblock %}

{% block content %}
  <h1>Create an account</h1>
  <p class="lead">
    Organisers set up a rota and its dates. Cooks claim the dates they can cover.
  </p>

  <div class="card form-card">
    <form method="post">
      {% csrf_token %}
      {{ form.as_p }}
      <button class="btn" type="submit">Sign up</button>
    </form>

    <p class="muted">
      Already have an account? <a href="{% url 'login' %}">Log in</a>.
    </p>
  </div>
{% endblock %}
Never leave out {% csrf_token %}. Without it Django rejects the form with a 403 Forbidden. It is a hidden field that proves the form came from your own site and not from an attacker's page. Every single <form method="post"> you ever write needs it.

07Put the links in your nav

In templates/base.html, find the <div class="nav-links"> block and replace everything between its opening and closing tags with this.

templates/base.html 
<a href="{% url 'rota:home' %}">Home</a>

{% if user.is_authenticated %}
  {% if user.is_staff %}<a href="{% url 'admin:index' %}">Admin</a>{% endif %}
  <span class="nav-user">{{ user.username }}</span>

  <form method="post" action="{% url 'logout' %}" class="logout-form">
    {% csrf_token %}
    <button type="submit" class="linklike">Log out</button>
  </form>
{% else %}
  <a href="{% url 'login' %}">Log in</a>
  <a class="btn btn-small" href="{% url 'rota:signup' %}">Sign up</a>
{% endif %}
The single biggest trap in this whole guide. Since Django 5.0, logging out must be a POST. Nearly every tutorial online still shows <a href="{% url 'logout' %}">Log out</a> — that is why it is a form with a button above. A plain link will give you 405 Method Not Allowed. You are on Django 5.2, so use the form.
user is always available in your templates. You never pass it in. That comes from django.contrib.auth.context_processors.auth, already in your settings. When nobody is logged in, user.is_authenticated is simply False.

10Write the automated tests

Your README promises tests, and the assessment marks them. Replace rota/tests.py with this.

rota/tests.py 
from django.contrib.auth.models import User
from django.test import TestCase
from django.urls import reverse

from .models import Profile


class SignUpTests(TestCase):
    """Registering creates a User, a Profile with the chosen role, and signs them in."""

    def test_signup_page_loads(self):
        response = self.client.get(reverse("rota:signup"))
        self.assertEqual(response.status_code, 200)
        self.assertTemplateUsed(response, "registration/signup.html")

    def test_signup_creates_user_and_profile(self):
        response = self.client.post(reverse("rota:signup"), {
            "username": "newcook",
            "email": "cook@example.com",
            "role": "cook",
            "password1": "Sturdy-Passphrase-42",
            "password2": "Sturdy-Passphrase-42",
        })

        self.assertRedirects(response, reverse("rota:home"))

        user = User.objects.get(username="newcook")
        self.assertEqual(user.profile.role, "cook")

    def test_mismatched_passwords_create_nothing(self):
        self.client.post(reverse("rota:signup"), {
            "username": "nope",
            "email": "nope@example.com",
            "role": "organiser",
            "password1": "Sturdy-Passphrase-42",
            "password2": "Different-Passphrase-43",
        })

        self.assertFalse(User.objects.filter(username="nope").exists())
        self.assertEqual(Profile.objects.count(), 0)


class LoginLogoutTests(TestCase):

    def setUp(self):
        self.user = User.objects.create_user(
            username="organiser1",
            password="Sturdy-Passphrase-42",
        )
        Profile.objects.create(user=self.user, role="organiser")

    def test_login_works(self):
        logged_in = self.client.login(
            username="organiser1",
            password="Sturdy-Passphrase-42",
        )
        self.assertTrue(logged_in)

    def test_logout_requires_post(self):
        """Django 5 refuses a GET to the logout view."""
        self.client.login(username="organiser1", password="Sturdy-Passphrase-42")

        self.assertEqual(self.client.get(reverse("logout")).status_code, 405)
        self.assertEqual(self.client.post(reverse("logout")).status_code, 302)

12When something goes wrong

What you seeWhat it meansFix
405 Method Not Allowed on logout Logout was a link, not a form Step 07 — it must be <form method="post">
403 Forbidden / CSRF verification failed A form is missing its token Add {% csrf_token %} inside every POST form
NoReverseMatch: 'signup' Wrong name in a {% url %} tag Your own app's URLs need the prefix: rota:signup. Django's built-in ones don't: login, logout
TemplateDoesNotExist: registration/login.html Folder misspelled or in the wrong place It must be exactly templates/registration/login.html
RelatedObjectDoesNotExist: User has no profile A user exists without a Profile — usually your superuser, created before this code existed Admin → Profiles → Add, pick that user, give them a role
Page loads with no styling DEBUG is off, so Django won't serve static files Run with DEBUG=True in front of the command
command not found: python The virtual environment isn't active source .venv/bin/activate — look for (.venv)

13What this unlocks

With login working you can now use @login_required above any view, and request.user inside one. That is what the next pieces need:

  • Rota CRUD — organiser=request.user when creating a rota
  • Slot claiming — slot.cook = request.user
  • Access control — comparing request.user to rota.organiser before allowing an edit

None of that is buildable until this step works, which is why it comes first.
